# ADR 0002：动效按上游还原，不用 StyleX

- 状态：已采纳
- 日期：2026-11-26
- 上游版本：meta/astryx `v0.7.17`

## 一句话结论

Astryx 好用，很大一部分功劳在动效设计上：
- 浮层从触发它的按钮处长出来；
- 拖动时元素紧跟手指，松手后带惯性滑行，到边缘有橡皮筋回弹；
- 列表增删时，其余各项平滑让位；
- 动画的时长和曲线都跟着主题走。

这些是组件体验的一部分，不是装饰。所以 astryx-vue 的移植目标是：在我们能做到的范围内，让用户看到的动效、手上感觉到的手感都和上游一致。

实现用普通 CSS 加 TypeScript，不引入 StyleX。

这和本仓库的总基调一致：还原上游，同时保证功能好用；用 Vue 做等价实现，必要时有所取舍。如果某个动效的取舍会让用户感觉明显不同，就写进 PR 说明。

## 怎么做

| 动效种类 | 实现方式 |
| --- | --- |
| 时长、缓动曲线、动效角色 | 主题包用 CSS 变量提供，组件 CSS 只读变量。关键帧统一放在 core 的一处，不重复定义 |
| 进场、退场 | Vue 的 `<Transition>` 或 CSS 过渡。有退场动画的浮层，等动画播完再卸载 |
| 由脚本驱动的动效（弹簧、惯性、橡皮筋、布局滑动） | core 内部的动效模块：纯 TypeScript，用 Web Animations API 或 `requestAnimationFrame` 驱动，不依赖 Vue |
| 手势（按压、拖动、轻扫、翻页吸附、手势仲裁） | core 内部的手势模块，建在指针事件上。对外只公开组合式函数，名字和参数对齐上游 |
| 「减少动态效果」 | 和上游一样读 `prefers-reduced-motion`，按上游对每种动效的规定替换，例如改成淡入淡出，或直接跳到终点。不是一律关掉 |

- 默认不引入第三方动画库。确实需要时，另写一份 ADR 说明理由。
- 单个源码文件不超过 500 行，动效模块也按职责拆成小文件。

## 移植时怎么判

- 上游改了动效，Vue 版组件的结构更简单，或者还没有这个动画，这都不是「不适用」的理由。
  - 缺的是动效或手势设施本身，就判「暂缓」，归到动效与手势引擎任务。
  - 不缺设施的，直接移植。
- 只有和 React 的渲染时机、StyleX 写法、上游内部工具链有关的改动，才判「不适用」。

## 怎么验收

- 测试要覆盖三点：
  - 时长、曲线确实读的是主题变量；
  - 「减少动态效果」打开时，走的是上游规定的替换方式；
  - 动画结束后组件的最终状态正确，例如焦点落在哪里、元素是否已卸载。
- 视觉上和上游的 storybook 对照，确认节奏、方向和落点一致。
