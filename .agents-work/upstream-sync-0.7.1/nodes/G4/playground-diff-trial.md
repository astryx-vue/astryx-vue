# 演练场模板自动对比：实测记录

## 一句话

`scripts/swarm/playground-diff.mjs` 能把「这个模板和原版像不像」变成数字。table、dashboard、login
各跑浅色深色一共 6 次，两边元素数量每次都完全对上（18/18、160/160、6/6），说明采集和配对没有跑偏。
dashboard 的 38 个偏差不是一个误报，是 3 个真实差异被重复计数（每个元素各算一次）。

| 模板 | 颜色 | 配成 | 偏差 | 缺失 | 多余 | 退出码 | 根因 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| table | light | 18 | 4 | 0 | 0 | 1 | 按钮字重 400 / 500 |
| table | dark | 18 | 4 | 0 | 0 | 1 | 同上 |
| dashboard | light | 160 | 38 | 0 | 0 | 1 | 按钮字重 + 表格单元格里 secondary 文字色 + 图表图例色块尺寸 |
| dashboard | dark | 160 | 38 | 0 | 0 | 1 | 同上 |
| login | light | 6 | 1 | 0 | 0 | 0 | 按钮字重 |
| login | dark | 6 | 1 | 0 | 0 | 0 | 同上 |

## 怎么跑

```sh
# 1. 构建并起 preview（vitepress dev 打开演练场会报 __VP_HASH_MAP__ is not defined）
env -u NODE_ENV pnpm docs:build
env -u NODE_ENV pnpm --filter @astryx-vue/docs preview --port 5181

# 2. 每次都要包在 browser-lock 里，一次跑一个模板一种颜色
export https_proxy=http://127.0.0.1:7890 http_proxy=http://127.0.0.1:7890 all_proxy=socks5://127.0.0.1:7890
node scripts/swarm/browser-lock.mjs run --purpose "演练场对比 table" --max-run 300 -- \
  node scripts/swarm/playground-diff.mjs table light 5181 --json /tmp/diff-table-light.json
```

单次 25–50 秒（原版要先编译，大约 13 秒才会把预览 iframe 换成正片）。下面的输出是 2026-10-28 在本机跑出来的。

## 38 个偏差拆开看：3 个根因，都是真的

调试时先怀疑配对写错了，于是一个一个回页面里量了 DOM，结论是三个真实差异，各自被重复计数：

1. **图表图例的色块尺寸不同 → 图例文字整体左移 4–12px（15 条）。**
   原版图例项是 `svg` 色块 12×12，我们的是 `<span class="legend-swatch">` 8×8，两边 `gap` 都是 8px。
   所以每个图例项前面少 4px，越靠后的项偏得越多（「Mobile」是这一行第 3 个，偏 12px）。
   这是真差异，不是配对错位：`All Users`、`NORAM`、`APAC` 这些每行第一项都只差 4px。
2. **表格单元格里的 secondary 文字色没生效（20 条）。**
   同一个 `astryx-text--type-supporting`，在卡片里算出来是 `rgb(71, 71, 71)`，放进 `<td>` 里却是
   `rgb(0, 0, 0)`；原版两种情况都是 `rgb(71, 71, 71)`。说明我们的 Table 给单元格盖了一层文字色，
   把 Text 的 `supporting` 盖掉了。深色下同理（原版 `rgb(158, 158, 158)`，我们 `rgb(255, 255, 255)`）。
3. **按钮文字字重 400，原版 500（dashboard 3 条，table 4 条，login 1 条）。**
   原版 Button 上写的是 `font-weight: medium`（500），我们的 Button 没设字重、继承到 400。
   table 模板的 4 个偏差全是这一条，login 的 1 个也是。

这三处都属于组件（Chart 图例、Table 文字色、Button 字重），不在这个脚本的范围里。修好以后
table 应该落到 0，dashboard 应该从 38 掉到个位数。

## 踩过的坑（写脚本时踩的，已修）

- **量外层元素的盒子会把「多包一层 span」算成位置 + 尺寸都不同。** 原版 `Name` 直接写在 `<th>` 里
  （盒子 227×37.5，x=0），我们多包了一层 `<span>`（38×21，x=16）。改成量文字自己的排版盒
  （对直系文本节点取 Range 的外包矩形）以后，两边的数字才对得上。
- **原版编译完之前，预览 iframe 里已经有 31 个脚手架元素。** 只看「iframe 里有内容」会采到脚手架，
  必须等「主页面不再显示 `Building`」并且「iframe 里的文字元素连续两次采样一样多」。
- **屏幕外的量字宽节点。** 原版 body 里有一个 `position: absolute; top: -20000px` 的 `<span>0</span>`，
  会被当成「缺失」。现在位置完全在左上角以外的元素不采。
- **图表画布和图例色块不能用同一套规则。** 图表画布是 860×300 的 `svg`，图例色块在两边一边是 svg、
  一边是 CSS 方块，混进来就是几十条误报。现在超过 64px 的 svg 一律当画布跳过，图例色块这种
  既不在控件里、又没有名字的小 svg 也不采。
