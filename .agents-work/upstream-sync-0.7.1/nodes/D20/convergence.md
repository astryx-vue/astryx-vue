# 演练场对齐的收敛规则（用户 2026-10-27 确认）

背景：担心「问题越找越多、永远无法收敛」。D12 第 2 批 16 个模板挖出 19 个 core 问题，D18 修 13 条，D12 又挖出 13 条交 D19。为了让它收敛，定下面几条。

1. **过关标准用数字**：用 `scripts/swarm/playground-diff.mjs` 对比原版和我们。一个模板偏差数 ≤ 3 且无缺失区块就算过。看截图只用来定位，不当过关依据。
2. **问题分三档，只修前两档**：必修＝缺区块、功能不对、颜色错、错位超过 2px。共用组件的根因才修＝1 到 2px 的偏差。不修只记一行＝亚像素，和原版自身的随机、数据差异。
3. **止损线**：D20 每批结束，总控统计「这一批新发现了几个 core 问题」，写进 `nodes/D20/convergence.md` 末尾的表。如果第 3 批的数字比第 1 批没有明显下降，就停下来找用户商量，不继续往下挖。
4. **目标版本冻结在原版 v0.7.1**：v0.7.2 到 v0.7.4 不混进来，等 G4 同步机制单独处理。
5. **范围固定**：D19 固定在 `nodes/D12/impl-3.md` 第三节的 13 条，不扩大；D19 修的过程中发现的新问题，记下来，不追加进 D19，由总控决定。
6. 「不修」只接受两种理由：在原版页面上实测过，确认是原版自身的随机、数据差异；或确实在 core 且已写进 core 问题清单。「差异小」不算。
