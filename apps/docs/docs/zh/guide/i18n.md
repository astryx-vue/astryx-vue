# 国际化

组件里需要句子的地方走语言包，不把中文或英文写死在每个调用点。随包带上的语言是 `en` 和 `zh-CN`。类型名 `AstryxLocale` 指的就是这两种。

在应用根上提供一次。子组件用 `useAstryxLocale` 和 `useAstryxMessages` 读取。没提供时，语言是 `en`。

```ts
import { provideAstryxLocale } from '@astryx-vue/core/locale'

provideAstryxLocale('zh-CN')
```

`provideAstryxLocale`、`useAstryxLocale`、`useAstryxMessages`、`normalizeLocale`、`loadAstryxCatalog` 和 `useCollator` 从 `@astryx-vue/core/locale` 引入，也会从 `@astryx-vue/core` 重新导出。`formatCalendarMonth` 和 `weekdayNames` 只在 `@astryx-vue/core/locale`。

`normalizeLocale` 把 `en` 和 `en-` 开头的标签收成 `en`，把 `zh`、`zh-CN`、`zh-Hans` 收成 `zh-CN`。`zh-TW`、`ja-JP` 会保留规范写法，用来接下面的额外语言。空的或解析不了的标签回到 `en`。

## 中文和英文以外

原版 Astryx 在 `packages/core/locales` 放了大约 30 份 React Intl JSON，包括 `ja-JP`、`zh-TW`、`ar-SA`。这些文件原样放在本包的 `locales/` 目录，没有手抄进 TypeScript。`loadAstryxCatalog` 按键映射进 `AstryxMessages`，再交给 `provideAstryxLocale` 的第二个参数。

对不上字段的键在返回值的 `unmapped` 里，原文还在，不会悄悄丢掉。这份 JSON 没覆盖到的字段继续用英文，路径在 `fallbackFields`。映射表里有、但这份 JSON 没给的键在 `missingKeys`。

内置的 `en` 和 `zh-CN` 仍是我们自己维护的短句。不要用原版 `en.json` 或 `zh-CN.json` 覆盖它们，两边用词并不相同。额外语言才走加载器。

```ts
import { loadAstryxCatalog, provideAstryxLocale } from '@astryx-vue/core/locale'
import catalog from '@astryx-vue/core/locales/ja-JP.json'

const loaded = loadAstryxCatalog('ja-JP', catalog)
provideAstryxLocale(loaded.locale, loaded.messages)
```

只调用 `provideAstryxLocale('ja-JP')`、不传入 `messages` 时，日期和 `useCollator` 会按日语工作，组件句子仍是英文。`zh-TW` 也不会自动改用简体中文。

要更新这些 JSON，改 `scripts/vendor-astryx-locales.mjs` 里的提交号，再运行 `node scripts/vendor-astryx-locales.mjs`。来源和许可证记在 `packages/core/THIRD_PARTY_NOTICES.md`。

## 按语言比较字符串

`useCollator` 返回当前语言的 `Intl.Collator`，包在 computed 里。没提供语言时用 `en`。

```ts
import { useCollator } from '@astryx-vue/core/locale'

const collator = useCollator({ numeric: true })
items.sort((a, b) => collator.value.compare(a.name, b.name))
```

`AstryxMessages` 是组件实际会读的句子。没出现在这个类型里的文字，由你传进去的 `label` 决定，切换语言不会改写它们。

文档站的中英文是 VitePress 的两套页面，地址分别在 `/` 和 `/en/`。那是文档的语言，不是 `provideAstryxLocale`。组件示例会按当前文档语言调用 `provideAstryxLocale`。
