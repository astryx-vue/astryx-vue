# 国际化

组件内部自带的提示文本（如搜索占位符、复制成功提示、清空按钮等）均走统一的语言环境管理，绝不把死板的中文或英文硬编码在每个组件里。随包默认内置的语言是英文（`en`）和简体中文（`zh-CN`）。在 TypeScript 类型定义中，`AstryxLocale` 指的就是这两种内置语言代码。

通常只需在应用的顶层根组件提供一次语言配置，下层所有子组件就可以自动通过 `useAstryxLocale` 和 `useAstryxMessages` 读取当前的语言文本。未配置时，默认使用英文。

```ts
import { provideAstryxLocale } from '@astryx-vue/core/locale'

// 全局配置为简体中文
provideAstryxLocale('zh-CN')
```

与国际化相关的常用函数（如 `provideAstryxLocale`、`useAstryxLocale`、`useAstryxMessages`、`normalizeLocale`、`loadAstryxCatalog` 和 `useCollator`）均可以从 `@astryx-vue/core/locale` 引入，在包根 `@astryx-vue/core` 也有重新导出。仅日历相关的底层格式化工具 `formatCalendarMonth` 和 `weekdayNames` 专属于 `@astryx-vue/core/locale`。

`normalizeLocale` 函数会自动标准化常见的语言标签：
- 把 `en`、`en-US`、`en-GB` 等以 `en` 开头的标签归一化为 `en`；
- 把 `zh`、`zh-CN`、`zh-Hans` 等归一化为 `zh-CN`；
- `zh-TW`、`ja-JP` 等则会保留标准写法，用来配合加载额外语言；
- 空值或无法解析的标签会自动回退到英文 `en`。

## 支持中文和英文以外的更多语言

原版 Astryx 在 `packages/core/locales` 目录下存放了约 30 份基于 React Intl 格式的语言 JSON 文件（包含 `ja-JP`、`zh-TW`、`ar-SA` 等）。我们将这些官方多语言资源完整同步在包内的 `locales/` 目录下。

你可以借助 `loadAstryxCatalog` 函数，将这些原版 JSON 转换映射为组件库可用的 `AstryxMessages` 结构，然后作为第二个参数传递给 `provideAstryxLocale`：

```ts
import { loadAstryxCatalog, provideAstryxLocale } from '@astryx-vue/core/locale'
import catalog from '@astryx-vue/core/locales/ja-JP.json'

// 加载日语语言包
const loaded = loadAstryxCatalog('ja-JP', catalog)
provideAstryxLocale(loaded.locale, loaded.messages)
```

加载器具备完善的容错处理：
- 如果原版 JSON 中某些键名在 Vue 版中未被使用，会保存在返回对象的 `unmapped` 属性中，避免数据悄悄丢失；
- 如果某项文本在 JSON 中缺失，会自动平滑回退到内置英文，涉及的字段路径记录在 `fallbackFields` 中；
- 如果组件需要某项文本但外部 JSON 根本没有提供，会记录在 `missingKeys` 中。

> **提示**：内置的 `en` 和 `zh-CN` 短句是我们专门为 Vue 场景精心润色调优过的。请不要用原版的 `en.json` 或 `zh-CN.json` 去覆盖它们，两者的用词风格有所不同。额外的第三方语言才建议通过该加载器引入。
>
> 如果只调用 `provideAstryxLocale('ja-JP')` 而没有传入转换后的 `messages`，那么组件内部的日期和字母排序会按日语规则运行，但组件自带的提示语仍会保持英文；同理，传入 `zh-TW` 也不会自动偷懒降级为简体中文。

如果你是维护者，需要同步原版最新语言包，只需修改 `scripts/vendor-astryx-locales.mjs` 中的 Git Commit 哈希，然后运行 `node scripts/vendor-astryx-locales.mjs`。来源与开源许可证说明记录在 `packages/core/THIRD_PARTY_NOTICES.md` 中。

## 按当前语言排序字符串（useCollator）

在不同国家和语言下，文字的排序习惯差异很大（例如拼音排序与注音、假名排序）。`useCollator` 函数返回一个基于当前语言环境的 `Intl.Collator` 实例，并包装在 Vue 的 `computed` 中。未设置语言时默认按英文处理：

```ts
import { useCollator } from '@astryx-vue/core/locale'

const collator = useCollator({ numeric: true })
// 按照当前语言环境自然排序
items.sort((a, b) => collator.value.compare(a.name, b.name))
```

## 区分组件内置文案与业务文案

`AstryxMessages` 仅管理组件库内置的通用文案（如「复制」、「清除」等）。你在业务中自己写进组件的文字（例如 `<Button label="提交表单" />` 传入的 `label`），是由你的业务代码完全掌控的，切换组件库语言不会去修改你的业务文字。

文档站顶部切换的中英文，是通过 VitePress 路由实现的两个完全独立的页面树（分别位于根路径 `/` 和 `/en/`），属于文档网站层面的多语言；而文档中的实时组件示例，则会自动根据当前页面的文档语言调用 `provideAstryxLocale`。
