# 国际化

组件内部内置的交互提示文本（如搜索占位符、复制提示、清空按钮等）统一由国际化模块管理，不会硬编码在组件模板中。随包内置的语言环境为英文（`en`）和简体中文（`zh-CN`）。在 TypeScript 类型定义中，`AstryxLocale` 指代这两种内置语言代码。

通常在应用顶层根组件提供一次语言配置后，所有子组件即可通过 `useAstryxLocale` 和 `useAstryxMessages` 读取当前的语言文本。未配置时默认使用英文。

```ts
import { provideAstryxLocale } from '@astryx-vue/core/locale'

// 全局配置为简体中文
provideAstryxLocale('zh-CN')
```

与国际化相关的常用函数（如 `provideAstryxLocale`、`useAstryxLocale`、`useAstryxMessages`、`useLocale`、`useTranslator`、`normalizeLocale`、`loadAstryxCatalog` 和 `useCollator`）均可从 `@astryx-vue/core/locale` 引入，在包根 `@astryx-vue/core` 中也有重新导出。日历相关的底层格式化工具 `formatCalendarMonth` 和 `weekdayNames` 仅在 `@astryx-vue/core/locale` 导出。

`normalizeLocale` 函数负责标准化常见的语言标签：
- 将 `zh`、`zh-CN`、`zh-Hans` 等归一化为 `zh-CN`，匹配内置的简体中文文本；
- 其它标签规范大小写并保留地区信息，如 `en-gb` 规范为 `en-GB`、`ja-jp` 规范为 `ja-JP`，使日期、数字与排序格式符合对应地区习惯；
- 内置翻译文案分为简体中文与英文两类：`en`、`en-GB`、`fr-FR` 等未提供自定义 `messages` 的语言标签，组件文本统一使用英文；
- 空值或无法解析的标签默认回退为 `en`。

## 在组件外部读取语言和翻译（useLocale、useTranslator）

组件内部涉及日期、数字、相对时间与排序的格式化逻辑，均读取最近一层 `InternationalizationProvider` 所提供的语言环境，不依赖 `navigator.language`。自定义格式化逻辑建议遵循相同规则：

```ts
import { useLocale, useTranslator } from '@astryx-vue/core/locale'

const { locale } = useLocale()
const { t } = useTranslator()

// 语言变了，这两个值会跟着变
const label = computed(() => new Intl.DateTimeFormat(locale.value).format(date))
const announce = () => t('@astryx.pagination.pageAnnounce', { current: 3 })
```

`t` 函数接收原版 `@astryx.*` 键并返回对应语言的格式化结果。未识别的键将原样返回，便于排查键名拼写；该函数亦可在事件回调中直接调用。

## 支持中文和英文以外的更多语言

上游 Astryx 在 `packages/core/locales` 目录下维护了约 30 份基于 React Intl 格式的语言 JSON 文件（包含 `ja-JP`、`zh-TW`、`ar-SA` 等）。我们将这些资源完整同步在包内的 `locales/` 目录下。

可以使用 `loadAstryxCatalog` 函数将这些 JSON 资源转换为组件库可用的 `AstryxMessages` 结构，并作为第二个参数传递给 `provideAstryxLocale`：

```ts
import { loadAstryxCatalog, provideAstryxLocale } from '@astryx-vue/core/locale'
import catalog from '@astryx-vue/core/locales/ja-JP.json'

// 加载日语语言包
const loaded = loadAstryxCatalog('ja-JP', catalog)
provideAstryxLocale(loaded.locale, loaded.messages)
```

加载器具备容错处理：
- 原版 JSON 中若包含当前 Vue 组件未使用的字段，将保存在返回结果的 `unmapped` 属性中；
- 若某项文本在 JSON 中缺失，会自动回退为内置英文，对应字段路径记录在 `fallbackFields` 中；
- 若组件所需的某项文本未在外部 JSON 中提供，对应键名记录在 `missingKeys` 中。

> **提示**：内置英文与原版 `en.json` 保持逐字一致，由 `pnpm check:i18n-catalog` 自动核验。内置 `zh-CN` 为针对中文表达优化的版本，请勿使用原版 `zh-CN.json` 直接覆盖。其它语言建议使用该加载器引入。
>
> 若仅调用 `provideAstryxLocale('ja-JP')` 而未传入转换后的 `messages`，组件内的日期和排序将遵循日语规则，但内置提示文本仍保持英文；同理，传入 `zh-TW` 也不会自动回退为简体中文。

维护者若需同步上游最新语言包，可执行 `node scripts/vendor-astryx-locales.mjs`，该脚本默认拉取上游 `main` 分支的最新提交；亦可传入指定提交号重现抓取过程。当前使用的提交记录在 `locales/SOURCE.json` 中，来源与开源许可说明见 `packages/core/THIRD_PARTY_NOTICES.md`。

同步完成后执行 `pnpm check:i18n-catalog`（该检查已包含在 `pnpm check` 中）。该命令将验证：

- 内置 `en` 和 `zh-CN` 字段完整且结构一致；
- 内置文案完整对应原版占位符，内置英文与原版英文逐字一致；
- 29 种语言的全部译文均可正常解析，占位符名称与语法（`{name}`、`number`、`plural`、`select`）与英文原文匹配，无无效键；
- 原版新增的所有键名，均已接入 `packages/core/src/locale/upstream/` 或在 `scripts/i18n-catalog/coverage.mjs` 中注明未接入原因。

## 字符串本地化排序（useCollator）

不同语言环境下的文本排序规则存在差异（例如拼音、注音或假名排序）。`useCollator` 函数返回基于当前语言环境的 `Intl.Collator` 计算属性（`computed`）。未设置语言时默认按英文规则排序：

```ts
import { useCollator } from '@astryx-vue/core/locale'

const collator = useCollator({ numeric: true })
// 按照当前语言环境自然排序
items.sort((a, b) => collator.value.compare(a.name, b.name))
```

## 组件内置文案与业务文案的区别

`AstryxMessages` 仅管理组件库内置的提示文案（如「复制」、「清除」）。业务代码直接传递给组件的文案（例如 `<Button label="提交表单" />` 中的 `label` 属性）完全由业务逻辑控制，组件库的语言切换不会修改业务文案。

文档站顶部的中英文切换基于 VitePress 路由实现的独立页面目录（分别位于根路径 `/` 和 `/en/`），属于文档站点的页面级多语言；文档中的交互示例则根据当前文档语言自动调用 `provideAstryxLocale`。

## 从右往左排版（RTL）与伪本地化测试

阿拉伯语、希伯来语、波斯语等语言采用从右往左的书写习惯。组件库已内置支持核心样式镜像，使用时需要完成以下两步配置。

### 第一步：声明书写方向

`InternationalizationProvider` 提供 `dir` 属性，取值为 `'ltr'` 或 `'rtl'`。若未显式指定，将根据 `locale` 自动推导：`ar-SA`、`he` 推导为 `rtl`，其余推导为 `ltr`。

推导逻辑基于 `getLocaleDirection()`。该函数优先通过浏览器的 `Intl.Locale` 获取文本方向；若浏览器尚未支持该 API，则回退至内置的从右往左语言列表（`ar`、`he`、`fa`、`ur`、`ps`、`sd` 等）。无法识别的标签统一作为 `ltr` 处理。

```vue
<script setup lang="ts">
import { InternationalizationProvider } from '@astryx-vue/core/InternationalizationProvider'
</script>

<template>
  <!-- 方向由 locale 推出来 -->
  <InternationalizationProvider locale="ar-SA">
    <App />
  </InternationalizationProvider>

  <!-- 语言是英文，但强制按从右往左排版：用来测布局 -->
  <InternationalizationProvider locale="en" dir="rtl">
    <App />
  </InternationalizationProvider>
</template>
```

在组合式函数中如需读取文本方向，可使用 `useLocaleDirection()`，该函数返回一个响应式 `ref`：

```ts
import { useLocaleDirection } from '@astryx-vue/core/InternationalizationProvider'

const direction = useLocaleDirection()
// 'ltr' 或 'rtl'
```

### 第二步：同步设置 DOM 的 dir 属性

`dir` 属性仅影响 Astryx 组件读取到的文本方向，它不会去修改 DOM。这一步必须业务代码处理，通常配置在 `<html>` 标签上：

```ts
import { getLocaleDirection } from '@astryx-vue/core/InternationalizationProvider'

// 浏览器里切换语言时同步一次
document.documentElement.dir = getLocaleDirection(locale.value)
document.documentElement.lang = locale.value
```

若未配置 DOM 节点的 `dir` 属性，页面排版、标点符号混排与滚动条位置将仍按照从左往右渲染，导致页面布局表现异常。

### 组件内部的处理机制

- **逻辑属性**：组件样式使用 `padding-inline-start`、`margin-inline-end`、`inset-inline-start` 等 CSS 逻辑属性。方向反转时数值自动镜像，无需编写第二套样式。
- **文本对齐**：使用 `text-align: start` 与 `end`，而非固定的 `left` 和 `right`。
- **特定组件适配**：提示框、悬浮卡片的 `start`、`end` 弹层在 `[dir='rtl']` 下自动反转对齐侧；面包屑分隔符反向渲染；滑块控制手柄使用 `:dir(rtl)` 进行位置微调。
- **键盘方向交互**：日历等组件直接读取 `document.documentElement.dir`，在从右往左模式下左右方向键交互逻辑相应反转，滚动计算亦按书写方向调整轴向。

这也是为什么第二步不能省：日历与滚动等底层计算依赖 DOM 实际的 dir 属性。

### 伪本地化测试（Pseudolocalization）

在接入完整语言包之前，可通过以下两个步骤进行排版健壮性测试：

1. 将 `dir` 与 `<html dir="rtl">` 均设为 `rtl`，验证整体界面布局是否正常镜像。
2. 将文案替换为较长的模拟文本，验证极端文本长度下容器是否溢出。

第二步可以使用 `overrides` 属性覆盖指定键名的文本：

```vue
<script setup lang="ts">
import { InternationalizationProvider } from '@astryx-vue/core/InternationalizationProvider'

// 键和原版语言包一致。这里故意写长，用来挤布局
const pseudo = {
  '@astryx.table.noData': '没有找到任何数据，这句话被故意写得很长很长，用来检查单元格会不会被撑破',
}
</script>

<template>
  <InternationalizationProvider locale="zh-CN" :overrides="pseudo">
    <App />
  </InternationalizationProvider>
</template>
```

### 排版检查要点

将方向切换为 `rtl` 并加长文案后，重点核对以下项目：

- 数字、价格与日期格式保持从左往右展示，未被错误倒置。
- 图标与文本的相对顺序正确：返回箭头指向右侧，下拉箭头位于文本左侧。
- 输入框光标初始位置位于右侧，占位文本靠右对齐。
- 侧边栏与抽屉面板镜像至右侧，拖拽分割手柄方向同步反转。哪一处未镜像，即说明该处样式写死了 `left` 或 `right`。
- 在长文本情况下按钮文案不折行、表格列宽不坍塌、卡片标题不超出边界。
- 表格中的数值列仍保持靠右对齐。

建议在深色模式与不同视口宽度下分别核验上述项目。
