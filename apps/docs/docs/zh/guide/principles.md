# 设计原则

本组件库的设计遵循以下四个核心原则：

- **组件优先**：已有组件覆盖的场景，直接使用组件，避免重复编写原生 HTML 和零散样式。
- **语义令牌**：颜色、间距、圆角等规范依据用途命名，而非依据视觉形态。例如命名为「正文主色」，而非「深灰」。
- **业务代码与主题解耦**：业务代码中避免出现硬编码色值与像素值，使主题切换与深色模式自动生效。
- **开放组合**：所有组件均导出并支持灵活组合，便于业务按需包装，无需破解组件内部封装。

## 八条实践规则

1. 优先使用组件库提供的标准组件。
2. 页面布局自外向内：先确定外壳和区域划分，再填充内容，详见 [页面布局](/guide/layout)。
3. 密集数据优先使用行排列：使用 `Table`、`List` 配合分隔线展示单行数据；`Card` 仅用于独立部件、图集或设置分组。
4. 自定义样式推荐使用标准 CSS，并放置在 `@layer astryx.overrides` 级联层内；与工具类库混用规则见 [主题与样式](/guide/styling)。
5. 样式值统一使用语义变量：如 `var(--astryx-color-text-primary)`、`var(--astryx-spacing-4)`。
6. 表单输入统一使用 `v-model` 双向绑定；`TextInput`、`CheckboxInput` 等组件均为受控模式。
7. 站内导航可通过 `as` 属性将根元素替换为 `RouterLink`，或在应用顶层配置 `LinkProvider`，避免使用原生 `<a href>` 导致整页刷新。
8. 属性不确定时通过命令行查询：`astryx-vue component Button`，避免编造不存在的 props。

## 主题解耦机制

主题样式表仅包含设计变量定义，不包含具体的组件结构样式。颜色变量采用标准语法声明：

```css
--astryx-color-text-primary: light-dark(#171717, #fafafa);
```

`light-dark()` 语法会依据当前元素的 `color-scheme` 自动计算浅色或深色值。业务代码只需引用 `var(--astryx-color-text-primary)`，深色模式即可自动生效，无需维护两套样式规则。

组件自身的结构样式同样引用统一的变量体系。当主题切换为 Gothic 等其它主题时，页面配色会自动更新，业务代码无需调整。

## 推荐实践与注意事项

| 指引 | 实践 |
| --- | --- |
| 推荐 | 用 `HStack`、`VStack`、`Grid` 摆放内容，它们不管颜色和边框。 |
| 推荐 | 颜色写 `var(--astryx-color-*)`，间距写 `var(--astryx-spacing-*)`。 |
| 推荐 | 不确定组件行为时，先跑 `astryx-vue component <名字>` 看一遍。 |
| 避免 | 在原生元素上堆内联样式，绕开组件。 |
| 避免 | 写死颜色（`#fff`）和间距（`16px`）。 |
| 避免 | 硬写 `<a href="/orders">`，站内跳转会整页刷新。 |
| 避免 | 每个列表项、每个页面区块都包一张 `Card`。 |
| 避免 | 拿 `Badge` 当纯装饰。它带含义：状态、分类、数量。只是个点缀的色块用 `Token`，只要一个圆点表示状态用 `StatusDot`。 |

## 样式技术方案说明

原版 Astryx 基于 StyleX 实现，astryx-vue 采用标准 CSS 配合 CSS 变量：组件样式全在 `@layer` 里，你在 `astryx.overrides` 层写自己的规则就能盖住它，不用靠增加选择器权重硬顶。

完整的分层顺序、`@layer` 该怎么排、怎么和 Tailwind 或 UnoCSS 一起用，见 [主题与样式](/guide/styling)。
