# Internationalization

Strings that the components speak come from a message catalog. They are not hard-coded at every call site. The supported locales are `en` and `zh-CN`. The type is `AstryxLocale`.

Provide the locale once at the root. Descendants read it with `useAstryxLocale` and `useAstryxMessages`. If nobody provides one, the locale is `en`.

```ts
import { provideAstryxLocale } from '@astryx-vue/core/locale'

provideAstryxLocale('zh-CN')
```

`provideAstryxLocale`, `useAstryxLocale`, `useAstryxMessages`, `normalizeLocale`, `formatCalendarMonth`, and `weekdayNames` come from `@astryx-vue/core/locale`. The first four are also re-exported from `@astryx-vue/core`.

`normalizeLocale` maps `zh` and any tag that starts with `zh-` to `zh-CN`. Everything else becomes `en`.

`AstryxMessages` covers `calendar`, `chat`, `citation`, `dateInput`, `markdown`, `multiSelector`, `nav`, `numberInput`, `pagination`, `selector`, `token`, `tokenizer`, and `typeahead`. A component that is not in that type does not rewrite its copy when the locale changes. That copy is the `label` you passed.

The Chinese and English docs are two VitePress trees, `/` and `/en/`. That is the documentation language, not `provideAstryxLocale`. Component examples call `provideAstryxLocale` for the language of the page you are reading.
